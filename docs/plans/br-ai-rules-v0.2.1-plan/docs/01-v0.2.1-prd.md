# BR AI Rules V0.2.1 PRD：默认资产文件化

## 1. 背景

BR AI Rules V0.2 已通过完整本地测试：默认初始化、stack 资产选择、自定义规则、managed block 分区保护、diff / sync / check / list / add、assets.include / assets.exclude、generated.json 快照和幂等性。

当前主要问题是：默认资产和默认规则仍然可能集中写在 TypeScript 代码中，导致资产不够直观、不可单独维护、不可复制、不可扩展。

产品方向是“规范规则资产平台”，因此默认资产必须文件化。

## 2. 目标

把内置默认 assets / rules 从代码内置结构迁移为 YAML 文件资产，并保持现有 CLI 行为不变。

## 3. 用户价值

- 可以在源码仓库中直接看到默认规则文件。
- 可以更容易新增、修改、审查规则内容。
- 可以为后续团队规则源、远程规则包、Web 规则资产平台打基础。
- 默认资产从“代码配置”变成“规则资产”。

## 4. 必做范围

1. 新增 `src/built-in/assets/*.yaml`。
2. 新增 `src/built-in/rules/*.yaml`。
3. 迁移当前所有内置 assets 到 YAML。
4. 迁移当前所有内置 rules 到 YAML。
5. 新增 built-in loader，从 YAML 加载资产和规则。
6. 保持现有 CLI 命令行为不变。
7. 保持 V0.2 全量测试通过。
8. build 后 `dist/built-in/` 中包含 YAML 文件。
9. README / CHANGELOG 补充 V0.2.1 说明。

## 5. 非目标

- 不做 Web 平台。
- 不做远程规则源。
- 不做 npm 规则包安装。
- 不做 GitHub source 下载。
- 不做 Agent / Skill / OpenSpec / Hook / Runtime。
- 不做复杂规则依赖冲突系统。
- 不改变用户已有配置格式。

## 6. 兼容要求

- `.ai-rules/config.json` 结构不破坏。
- `assets.include / assets.exclude` 继续可用。
- `rulesets` 兼容迁移逻辑继续可用。
- `.ai-rules/rules/*.yaml` 自定义规则继续自动发现。
- `generated.json` 格式不破坏，允许追加字段。

## 7. 成功标准

完成后，源码仓库中必须能看到：

```text
src/built-in/assets/
src/built-in/rules/
```

并且命令仍然可用：

```bash
npm run typecheck
npm test
npm run build
node dist/cli.js init --stack react,typescript
node dist/cli.js check
node dist/cli.js list --assets
```
