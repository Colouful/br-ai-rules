# BR AI Rules V0.3 PRD: Team Rule Sources and Asset Upgrade

## Background

V0.2 已经解决：

- 一套内置资产按技术栈生成规则文件
- 项目自定义规则
- AGENTS.md / CLAUDE.md / Cursor Rules
- sync / diff / check / list / add
- 真实前后端项目 dogfood

但团队真实使用时会出现新问题：

- 多个项目需要复用同一套团队规则
- 团队规则不应该复制粘贴到每个项目
- 团队希望有 frontend-standard、backend-standard 等规则资产
- 团队规则升级后，需要知道哪些规则变化影响了项目
- generated.json 需要记录 source、asset、rule 快照

## Product Goal

让 BR AI Rules 支持本地团队规则源，让团队可以在独立目录或独立仓库中维护规则资产，并在项目中引用。

## User Stories

### Story 1: 初始化项目时使用团队规则源

```bash
br-rules init --stack spring-boot,java,mysql,redis --source ../team-ai-rules --asset team.backend-standard
```

### Story 2: 查看项目使用了哪些规则源

```bash
br-rules source list
```

### Story 3: 查看可用资产和启用资产

```bash
br-rules asset list
```

### Story 4: 团队规则变更后查看 diff

```bash
br-rules diff
```

## Success Criteria

- 可以从 local source 加载 assets 和 rules
- 可以用 `init --source --asset` 初始化项目
- source asset 中的 rules 能渲染进 AGENTS.md / CLAUDE.md / Cursor Rules
- check 能校验 source asset / source rule
- generated.json 能记录 source snapshot
- diff 能显示 source asset 导致的文件变化
- V0.2 功能不回归

## Non Goals

- 不做 GitHub remote source
- 不做 npm source
- 不做 Web 平台
- 不做权限 / 登录
- 不做自动升级命令
- 不做 Agent / Skill / Hook / Runtime
- 不做 `br-rules verify`
